# RC_DeepSpatial 服务器环境安装与保存指南

本指南整理自本次服务器环境恢复过程，以运行 **RC_DeepSpatial** 为主。适用基线是用户提供的 NVIDIA PyTorch 24.03 镜像环境：Python 3.10、PyTorch `2.3.0a0+40ec155e58.nv24.3`、torchvision `0.18.0a0`、NumPy `1.24.4`、SciPy `1.12.0`。

命令中的服务器项目根目录为 `/3250608056/code/DeepSpatial`；如果实际位置不同，请替换路径。本文不是完整镜像锁文件，也不表示已经在服务器完成全部运行验证。

## 1. 已安装环境的结论

按最后一次提供的 `pip list`，RC 所需依赖均已安装，无需再次执行安装步骤，可以直接跳到第 4 节验证。

### 2.1 确认基础环境

```bash

```

下面的方案复用镜像自带的 GPU 包，不需要重新下载 PyTorch、torchvision 或安装 CUDA。

### 2.2 锁定镜像自带的关键包

在同一个终端中执行。此文件放在 `/tmp`，重建容器后需要重新生成。

```bash
python - <<'PY'
from importlib.metadata import version
from pathlib import Path

packages = ['torch', 'torchvision', 'numpy', 'scipy', 'numba']
path = Path('/tmp/deepspatial-image-constraints.txt')
path.write_text(
    '\n'.join(f'{name}=={version(name)}' for name in packages) + '\n',
    encoding='utf-8',
)
print(path.read_text())
PY
```

### 2.3 安装 RC 所需包

以下直接依赖版本参考本次最终提供的环境列表；间接依赖仍由 pip 解析。清华源不可用时，可将地址换成 `https://pypi.org/simple`。

```bash
python -m pip install \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  -c /tmp/deepspatial-image-constraints.txt \
  'pandas==2.2.3' \
  'timm==0.9.16' \
  'anndata==0.10.8' \
  'POT==0.9.5' \
  'torchdiffeq==0.2.5' \
  'scikit-learn==1.5.2' \
  'joblib==1.3.2' \
  'h5py==3.11.0' \
  'protobuf==3.20.3'
```

镜像中的 NumPy `1.24.4` 和 SciPy `1.12.0` 已符合 RC 要求。安装后不要为了消除警告将 pandas 降回 `1.5.3`，因为 RC 声明要求 pandas >=2.0。

如果需要在 Notebook 中运行，而镜像里没有内核支持，再安装：

```bash
python -m pip install \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  -c /tmp/deepspatial-image-constraints.txt \
  'ipykernel==6.29.3'
```

本次提供的环境已安装 ipykernel。Notebook 应选择与上述 `python` 对应的内核；安装或更换包后重启内核。

## 5. 恢复数据并启动实验

### 5.1 检查数据文件

默认配置 `RC_DeepSpatial/configs/merfish.json` 的 `input_glob` 相对于 `RC_DeepSpatial` 目录解析，要求在下列目录及其子目录中找到恰好五个文件：

```text
/3250608056/code/DeepSpatial/data/merfish_mouse_hypothalamus/
  merfish_0.h5ad
  merfish_1.h5ad
  merfish_2.h5ad
  merfish_3.h5ad
  merfish_4.h5ad
```

检查当前配置实际找到的文件：

```bash
python - <<'PY'
import glob
import json
from pathlib import Path

project = Path('RC_DeepSpatial').resolve()
config = json.loads((project / 'configs/merfish.json').read_text(encoding='utf-8-sig'))
paths = sorted(glob.glob(str(project / config['input_glob']), recursive=True))
for path in paths:
    print(path)
print('文件数:', len(paths))
assert len(paths) == len(config['slice_z_um']), '数据文件数量与配置不一致'
PY
```

如果数据保存在其他位置，修改配置中的 `input_glob`。修改实验配置后，应使用新的输出目录。

### 5.2 先运行真实数据诊断

```bash
CUDA_VISIBLE_DEVICES=0 bash RC_DeepSpatial/scripts/run_python.sh \
  RC_DeepSpatial/examples/run_merfish.py \
  --stage audit --holdouts 2 --arms control ABC \
  --device cuda:0 \
  --output RC_DeepSpatial/outputs/pairing_audit
```

`audit` 会读取可见切片、建立配对并执行数据诊断，不训练流模型。输出目录需要尚不存在；复用相同实验时使用 `--resume`。

### 5.3 正式运行

```bash
CUDA_VISIBLE_DEVICES=0 bash RC_DeepSpatial/scripts/run_python.sh \
  RC_DeepSpatial/examples/run_merfish.py --device cuda:0
```

默认执行留出折 1、2、3，seed 42，以及 baseline、control、R0、A、B、AB、ABC 七个实验臂；每个预训练或残差训练阶段为 100 epochs。默认结果目录为 `RC_DeepSpatial/outputs/merfish_v1/`。

Notebook 入口为 `RC_DeepSpatial/examples/run_merfish.ipynb`。更改物理 GPU 后需重启内核，并从第一格重新执行。

## 6. 本次遇到的报错与警告

### 6.1 ONNX / protobuf 导入错误

典型报错：

```text
TypeError: Descriptors cannot not be created directly.
```

本次堆栈是 Lightning 导入 PyTorch 的相关模块时触发旧版 ONNX 生成代码，与 protobuf 4.x 不兼容。修复：

```bash
python -m pip install \
  -i https://pypi.tuna.tsinghua.edu.cn/simple \
  'protobuf==3.20.3'
```

如果在 Notebook 中运行，修复后重启内核。最后提供的环境列表已是 `protobuf==3.20.3`，无需重复降级。

### 6.2 pandas 与 RAPIDS 的版本冲突

本镜像的 `cudf/dask-cuda/dask-cudf 24.2.0` 要求 pandas <1.6，而 RC 要求 pandas >=2.0，因此它们在同一 Python 环境中的声明要求无法同时满足。

RC 当前代码不直接使用这些 RAPIDS 包。只运行 RC 时保留 pandas 2.2.3，并以第 4 节的导入和工程检查确认 RC；如果还需要使用 RAPIDS，则为 RAPIDS 与 RC 分开建立环境或镜像。不要把整个镜像认定为依赖完全无冲突。

### 6.3 torchtext 的 PyTorch 版本警告

镜像里的 torchtext 要求的 PyTorch 版本字符串与 NVIDIA 定制版本不同。RC 不使用 torchtext；不要仅为消除此警告替换镜像自带的 PyTorch。

### 6.4 输出目录已存在

典型报错：

```text
FileExistsError: .../holdout_1/seed_42 exists; choose a new output root or --resume.
```

这是防止覆盖结果的保护机制，与依赖安装无关。

继续相同实验，在终端加 `--resume`：

```bash
CUDA_VISIBLE_DEVICES=0 bash RC_DeepSpatial/scripts/run_python.sh \
  RC_DeepSpatial/examples/run_merfish.py --device cuda:0 --resume
```

Notebook 中，在实验运行格前设置：

```python
RESUME = True
```

续跑要求配置、源码和可见输入与已有记录一致。程序会检查已有状态，跳过已完成部分或从检查点恢复；配置、源码或可见输入发生变化时，使用新的输出目录。

重新从头运行，可在 Notebook 配置格中设置一个尚不存在的目录：

```python
OUTPUT = PROJECT / 'outputs' / 'merfish_v2'
RESUME = False
```

不要直接删除旧结果来绕过目录保护。

## 7. 记录环境并保存为自己的镜像

完成依赖验证和项目试跑后，在项目根目录记录环境：

```bash
python -m pip freeze > RC_DeepSpatial/environment-freeze.txt
python -m pip list --format=json > RC_DeepSpatial/environment-packages.json
python -m pip check > RC_DeepSpatial/environment-pip-check.txt 2>&1
```

`pip check` 可能报告上面记录的镜像包冲突，应保留日志。`pip freeze` 中可能包含 NVIDIA 定制包和本地可编辑路径，适合作为记录，不宜直接用于在任意环境中完整重装。

### 云算力平台

如果平台支持，在控制台使用“保存镜像 / 制作镜像 / 自定义镜像”等功能保存当前环境。保存范围和入口以平台说明为准；创建新实例后再次执行第 4 节验证。

### 可管理 Docker 的服务器

以下命令在管理目标容器的 **Docker 宿主机** 执行，通常不是容器内的训练终端。将 `容器ID` 替换为实际值。

```bash
docker ps -a
docker commit 容器ID deepspatial-rc:v1
docker run --gpus all -it deepspatial-rc:v1 bash
```

`docker commit` 保存的是容器文件系统改动，不包含挂载目录里的内容。若 Python 环境、项目代码、数据或模型位于挂载目录，需要单独备份并在新容器中重新挂载。

为避免镜像随服务器清理而丢失，可以推送到自己的镜像仓库，或导出备份：

```bash
docker save -o deepspatial-rc-v1.tar deepspatial-rc:v1
```

将导出的文件复制到服务器以外的备份位置。需要恢复时：

```bash
docker load -i deepspatial-rc-v1.tar
```
